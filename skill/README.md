# Reusable skill package

This package extracts three workflows from the project. Each has a `SKILL.md` entrypoint and a copyable record template. Another team can give its own source, configuration, logs, and firmware identity to an agent, then ask it to follow the relevant entrypoint. Copy only the selected skill folder into an agent's skills directory if automatic discovery is desired. Do not copy this project's sensor thresholds or board pin numbers as universal defaults.

## Observations that led to the skills

- During earlier board debugging, some displayed channels had values while other channels did not. Treating every blank value as a damaged sensor skipped the UART/I2C, raw-event, and validity boundaries. That led to the layered diagnosis record. Those older observations are not validation of the released new bitstream.
- A heart-rate value once disagreed with an independent reference. A smooth output curve alone could not distinguish poor raw contact, feature extraction, stale data, or filter behavior. That led to the evidence matrix, which requires paired raw/feature/validity evidence before making a dynamic claim. No personal measurement is bundled here.
- The source serves one optical device and two temperature devices through one I2C master at different requested rates. Address ambiguity and a missing result are easier to review with a device/address/transaction plan than with a screen value alone. That led to the shared-bus scheduling skill; source review and build success remain separate from board measurements.

## What the package does not claim

These skills are portable review and troubleshooting methods, not clinical diagnostic rules. The current 100 MHz bitstream has timing and simulation evidence but no board liveness check. The 25 MHz baseline has a four-channel liveness check, but no independent four-sensor accuracy or fault-recovery acceptance run. Prior observations from another firmware are not proof for the new image. A generic PYNQ Overlay, register-map, or DMA skill is not included because this source does not contain a verified PL-to-ARM data producer. The independent release-path check remains at `build/check_paths.py` and is not counted as one of the selected skills.

## Reuse prompt

> Read `skill/<selected-skill>/SKILL.md` and its linked template. Apply it to this new project's exact source, configured part, firmware hash, and available measurements. Fill each required evidence field; mark absent observations as pending. Return the finding, its supporting file/log locations, the first uncertain layer, and one next discriminating check. Do not invent readings or transfer this repository's thresholds, addresses, or board pins to the new project.
