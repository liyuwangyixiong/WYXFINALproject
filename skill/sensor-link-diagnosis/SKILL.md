# Sensor link diagnosis

适用于传感器已接到 FPGA/SoC，但某路无数据、数值异常或显示不更新的排障。目标是找出**最后一个有证据正常的层**和**第一个有证据异常的层**，并给出下一项最小检查。它不预设具体板卡、传感器型号或医学阈值。

1. 先建立证据身份：工程提交或源码版本、已烧录固件哈希、板卡与传感器、供电方式、接口、采集时间。旧固件的波形不能证明新固件正常。
2. 按层核对：时钟/复位和供电 → 引脚/共地/电平 → 总线事务或串口帧 → **真实新样本**事件 → 原始数据质量 → 特征值与有效标志 → 消费端显示。共享总线要同时看其他地址；独立接口可作对照。不要把轮询次数当样本数。
3. 每层记录“实测正常 / 实测异常 / 未测”，只在有日志、波形、万用表值或寄存器读数时填写“实测”。照片、线色和指示灯可辅助定位，不能单独证明电压、地址、ACK 或波形正确。
4. 输出一句可检验的当前结论、尚存的其他可能性，以及一项风险最小的下一步检查。未知接线先断电核对，再移动跳线；不要通过反复上电试错来猜供电极性。
5. 用 [排障记录模板](references/triage_record.md)记录结果。若关键层不可观测，明确写“证据不足”，不要把“当前不可用”升级成“器件已损坏”。

## 在本工程中的已验证效果与边界

源级走查确认了独立 UART 心率链和共享 I²C 链的分界：`src/rtl/kpt_d01_uart_hr.sv`分别给出帧、格式/超时和新样本事件；`src/drivers/sensor_acquire.v`把 MAX30102、室温 TMP117、探头 TMP117 调度在同一 I²C 主机上，并分别给出原始有效事件和错误码。因此可以先区分“多器件共用链路故障”“单地址故障”“原始样本后处理故障”三类待检假设。**这是源码结构核对，不是新版 bit 的四路实物验收**；现有发布版不含 ILA，若现场没有独立采集手段，部分层只能标为未测。

## 失效条件

- 无法确定实际烧录固件或采集时间，导致日志和源码不能对应。
- 缺少关键层的可观测信号、供电测量或通信记录；此时只能列假设，不能确认故障器件。
- 传感器本身有复用地址、外部多路复用器、异步时钟域或专用模拟前端；应按实际接口重新画链路，不套用本工程地址/阈值。
