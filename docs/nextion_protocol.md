# Nextion NX4832F035 显示集成

本目录实现《串口屏开发目标草案》的状态、四项指标、全部故障原因、四路可切换趋势和显示链路超时处理。主控采用 PL 侧 UART，直接连接现有四路监测核心；原工程六个 RTL 不修改。当前核心处理的是已经计算出的指标，不包含传感器 I²C 采集或原始 PPG 算法。

## 文件与使用

- `HealthMonitor.HMI`：Nextion Editor 1.68.2 创建的可编辑原生工程，NX4832F035_011、90° 横屏、480×320、GB2312。
- `HealthMonitor.tft`：官方编辑器编译并导出的屏幕固件。请核对实物完整型号后按官方烧录流程使用。
- `rtl/health_nextion_top.sv`：原四路核心与显示模块的集成顶层。
- `rtl/nextion_display.sv`：可信度缓存、显示转换、快照与趋势调度。
- `rtl/nextion_link.sv`、`rtl/uart_8n1.sv`：命令应答与全双工 UART。
- `hmi_events/`、`hmi_components.json`：页面事件源代码与控件清单。`tools/generate_hmi_events.py` 可重新生成这些文本；生成后仍须将变更写入 HMI 并在官方编辑器重新编译，不能只改文本就认为固件已更新。
- `evidence/`：仿真日志、综合报告及原生模拟器截图。截图和验证输入均为模拟验证，不是人体或实物传感器采集。

已建立独立工程 `vivado/health_nextion.xpr`，可直接用 Vivado 2024.1 打开，顶层为 `health_nextion_top`。它以相对路径引用原核心和本目录 RTL，不改原 `.xpr`，也未向 `sim_1` 加入验证夹具。复制工程时请保留本目录与旁边 `WYXproject` 的相对位置。若需要在新位置重建，可在 Vivado Tcl Console 执行 `source {D:/Cheng Zhai/Desktop/FPGA/nextion_display/tools/create_project.tcl}`；脚本会拒绝覆盖已有独立工程。也可将四个新 RTL 手动加入已有系统，使用集成顶层或单独实例化 `nextion_display`。

## 主控接入

`aclk` 默认 100 MHz；`aresetn` 同步低有效，`tick_1ms` 必须是同一时钟域内每毫秒一个时钟宽度的脉冲。实际时钟不同时须修改 `CLK_HZ`。四路核心原有配置、门限和输入单位保持不变。

输入最终指标在 `smooth_valid && smooth_ready` 时接收。显示适配层的四路 ready 在复位释放后始终为 1，串口断线不会阻塞监测。可用条件为 `feature_available & ~device_isolated`，且必须已有此有效期间收到的新结果。失效即清除缓存有效标志；恢复可用之后仍需新结果，不能恢复旧读数。

集成顶层将原本外接的四路 smooth_ready 接到显示层，其余监测端口和参数沿用核心。`nextion_tx` 接屏幕 RX，`nextion_rx` 接屏幕 TX，双方共地。**物理管脚、板卡 IO 电压、供电与电平适配尚未确定，未填写 XDC 管脚，也未生成板级 bitstream。** 必须依据实际板卡及屏幕电气规格完成这部分接线；本交付不以猜测的接线代替板级设计。

状态严格使用核心编码：0 正常、1 预警、2 危险、3 系统错误；若独立 system_error 为 1，防御性显示系统错误。范围告警仅在数值可信且该路配置正常时标红，仍保留实际读数。每颗器件一行，三个确认原因可以并列；待确认、配置异常与隔离分别显示。核心未单独输出“预热/过期”分类，所以当前统一显示“等待/过期”，不推测器件损坏。

## 通信参数与刷新

115200 baud、8N1、空闲高电平。每条 ASCII 指令以 `FF FF FF` 结束。只允许此显示驱动作为该串口命令发送方。

正常刷新/心跳周期 250 ms，趋势采点 1000 ms。每条命令等待 `01 FF FF FF` 成功回包，超时 150 ms；错误应答、异常接收、屏幕启动或切页会触发重新同步。恢复静默 300 ms 后依次发送 `bkcmd=3`、`page 0` 和完整快照。状态、可信度与故障变化在命令边界中止尚未提交的旧快照，立即重新采样。

每帧先写全部 `s00`～`s18` 全局整数，再发 `click m0,0`。页面只在该事件内提交显示，避免逐字段更新时混合有效性与旧数值。序号相同不会重复添加趋势点；只有提交刷新看门狗。屏幕超过约 2 秒没有完整提交即显示“通信中断 / 状态未知”，撤下全部实时读数并清空趋势。该提示不是第五种健康状态。

串口发送耗时和屏幕执行速度影响实际延迟。仿真已检查紧急失效在 500 逻辑毫秒内提交，但 **实物屏幕的 500 ms 响应、连续运行和闪烁情况仍须板级联调测量**。改变波特率、趋势周期或看门狗配置时必须同步修改 HMI 文案/程序，不能只改单侧参数。

## 字段协议 V1

四路位序固定为 bit0 心率 MAX1、bit1 血氧 MAX2、bit2 体温、bit3 室温。

| 字段 | 含义 |
| --- | --- |
| s00 | 核心系统状态 0～3 |
| s01 | 可显示数值的四路掩码 |
| s02 | 已隔离掩码 |
| s03 | 可信且配置正常的越界掩码 |
| s04 | 配置异常掩码 |
| s05 | 确认故障原因，通道 c 占 bits 3c+2:3c；三位分别为通信、无更新/冻结、PPG 质量 |
| s06 | 异常待确认原因，同 s05 位序 |
| s07 | 心率整数 bpm，输入 ×100 四舍五入 |
| s08 | 血氧百分比 ×10，输入 ×100 四舍五入 |
| s09 / s10 | 体温 / 室温绝对值 ℃×10，由有符号 Q7 四舍五入 |
| s11 | 温度负号，bit2 体温、bit3 室温；零不带负号 |
| s12 / s13 | 本帧趋势添加 / 清空掩码；先清空后添加 |
| s14～s17 | 四路趋势 Y 坐标 0～47 |
| s18 | 16 位递增帧序号，允许回绕 |

无效字段中的数值不得解释为读数，以 s01 为准。页面初始 last=65536，保证首帧和序号回绕可正常接收。

## 页面与趋势

上方 176 px 为状态及四颗器件信息，中间 62 px 为指标，下方为趋势。触摸体温、室温、心率或血氧读数区域切换曲线。状态始终保留。

| 指标 | 显示精度 | 趋势纵轴 |
| --- | --- | --- |
| 心率 | 整数 bpm | 40～180 bpm |
| 血氧 | 0.1% | 80～100% |
| 体温 | 0.1℃ | 34～42℃ |
| 室温 | 0.1℃ | 0～50℃ |

趋势固定每秒最多一个点，仅使用该时间窗内收到的新结果。缺样或失效清空该路历史，不重复旧值、补零或跨缺样连线。纵轴外的可信值在曲线边缘截断，数字区继续显示实际值。440 px 宽曲线约容纳 440 个点；持续有新数据时约为 7 分 20 秒。四张原生波形控件独立缓存、同位置显示，切换不混用通道。重启/重新建页清空历史，不承诺跨页恢复或长期存储。

编译器的 5 条重叠警告来自四张互斥显示的曲线和三个禁止物理触摸的内部事件热点。已在模拟器验证四项切换和断线提示。t0/t1 为隐藏字符串暂存控件；m0 提交，m1～m4 切换，m5 刷新趋势选择，m6 断线显示，tm0 为 100 ms 看门狗。
